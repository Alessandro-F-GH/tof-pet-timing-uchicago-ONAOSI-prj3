\section{Waveform preprocessing and dataset construction}\label{sec:preprocessing}

\subsection{TRC-to-ROOT conversion}

The oscilloscope data are initially stored as one \texttt{.trc} file per channel and event. 
A C++ converter in the repository groups the four channels of each event and writes one ROOT file per acquisition run. 
For each event and channel, the ROOT representation preserves the original signed 16-bit analogue-to-digital converter 
samples together with the sample count, vertical gain and offset, horizontal sampling interval and time offset, 
and the event and source-file identifiers. The converter performs no timing or event-selection analysis.

Physical voltage and time are reconstructed in the analysis code from the stored calibration metadata. 
Keeping the raw samples as 16-bit integers reduces the intermediate data volume while preserving the acquisition information 
required by the later waveform analysis.

\subsection{Event selection}

Event selection is applied before the timing analysis. 
The selection criteria are determined from the development population and then applied unchanged to the remaining events
(we retain a subset of the data for the final unbiased evaluation).

\paragraph{Energy photopeak.}

For each detector, the maximum amplitude of the energy waveform is used to build the pulse-height distribution. The dominant high-amplitude peak 
is identified from a smoothed histogram and fitted iteratively with a Gaussian function. 
After each iteration, the fit interval is updated around the fitted mean and standard deviation until convergence or the maximum number of iterations 
is reached.

The final photopeak selection interval is defined from the fitted Gaussian parameters as

$$
    \mu - 2\sigma
    \leq A
    \leq
    \mu + 4\sigma .
$$

An event is retained only if the energy signals from both detectors fall inside their respective photopeak intervals.

\paragraph{Timing-channel pulse selection.}

The timing channel has a considerably higher gain and may contain multiple threshold crossings caused by electronic noise or secondary pulse structures. For this reason, timing-channel events are additionally selected using the pulse time over threshold (ToT).

Candidate hits are first identified using a fixed trigger level of \SI{120}{mV}. For each detector, the distribution of candidate pulse durations 
is then constructed from the development events that already satisfy the photopeak selection. 
As for the energy photopeak, the dominant ToT peak is identified and fitted with the same method used for the photopeak selection.

The accepted ToT interval is
$$
\mu_{\mathrm{ToT}}-3\sigma_{\mathrm{ToT}}
\leq
\mathrm{ToT}
\leq
\mu_{\mathrm{ToT}}+3\sigma_{\mathrm{ToT}} .
$$

If more than one timing hit falls inside this interval, the hit whose duration is closest to the fitted ToT peak is selected. This suppresses spurious threshold crossings and rejects events with an anomalous timing-channel response.

\paragraph{Baseline-noise filter.}

A pre-trigger waveform interval is used to reject events affected by excessive baseline fluctuations. 
For each detector, the baseline root-mean-square (RMS) value is calculated in an interval (\SI{-4}{ns} , \SI{-1}{ns}) relative to the selected trigger.

The baseline-noise threshold is estimated from the development population. Let \(R\) denote the distribution of baseline RMS values for a given detector channel. Its central value is estimated by the median, while the dispersion is estimated using the median absolute deviation (MAD), converted to a Gaussian-equivalent scale:

$$
\sigma_{\mathrm{MAD}}
=
1.4826\,
\operatorname{median}
\left(
\left|R-\operatorname{median}(R)\right|
\right).
$$

The maximum accepted baseline RMS is then:

$$
R_{\max}
=
\operatorname{median}(R)
+
5\,\sigma_{\mathrm{MAD}}.
$$

Events with \(R>R_{\max}\) in either detector channel are rejected.

The threshold is calculated independently for the two detector channels, and an event is retained only if the baseline RMS is 
below the corresponding limit for both detectors.

\subsection{Leading-edge timing and calibration}

Leading-edge discrimination (LED) provides the reference timing estimate for each detector. 
For every waveform, the LED threshold is defined as a fixed voltage offset above the mean pre-trigger baseline. 
The crossing time is then determined by linear interpolation between the two samples surrounding the rising-edge threshold crossing.

The detector-pair LED time difference is
\begin{equation}
    \Delta t_{\mathrm{LED}} = t_{\mathrm{LED},1}-t_{\mathrm{LED},2}.
\end{equation}

A constant inter-channel timing offset is estimated from the training data:
\begin{equation}
    \widehat{C}_{12}
    =
    \operatorname{mean}_{\mathrm{train}}
    \left(\Delta t_{\mathrm{LED}}\right)
    -
    \mathrm{TOF},
\end{equation}
where TOF denotes the known physical time-of-flight offset for the acquisition geometry.

The supervised target is the calibrated LED residual,
\begin{equation}
    y_{\mathrm{target}}
    =
    \Delta t_{\mathrm{LED}}
    -
    \mathrm{TOF}
    -
    \widehat{C}_{12}.
\end{equation}
The network therefore learns an event-by-event correction to LED timing rather than predicting the physical TOF directly.

\subsection{Machine-learning input}

For each event, the waveform of each detector is aligned to its leading-edge discrimination (LED) crossing time. 
A fixed time window around the aligned crossing is then extracted and used as input to the machine-learning model.

The locally connected model receives the waveform samples in their original temporal order, so each local receptive field 
always contains neighboring samples from the signal.

Waveform amplitudes are normalized using the fixed physical voltage range of the oscilloscope acquisition. 
This preserves the relative amplitude information of the detector signal and ensures that the same physical voltage 
is mapped to the same normalized value for every event.

\subsection{Waveform windows}

Two temporal windows are evaluated after LED alignment. The shorter \emph{Onishi window},
\[
    [-1.5,\,2.0]~\mathrm{ns},
\]
focuses on the waveform region immediately surrounding the threshold crossing and is used as the reference window for comparison with the waveform-based CNN approach of Onishi et al.~\cite{onishi2022}. A second, wider window,
\[
    [-2.0,\,30.0]~\mathrm{ns},
\]
retains a substantially larger portion of the pulse evolution.

Using both windows separates two questions: whether the proposed model can extract useful timing information from the short region used for the literature-based comparison, and whether additional information contained later in the waveform further improves the correction. Apart from the temporal extent, the preprocessing and amplitude scaling are kept unchanged.

\subsection{Coincidence timing resolution}

Coincidence timing resolution (CTR) is estimated directly from the timing-residual distribution using a robust interval-based method. 
The residuals are sorted and the narrowest interval containing \(90\%\) of the events is identified. 
If \(w_{90}\) denotes the width of this interval, it is converted to the full width at half maximum (FWHM) of a Gaussian distribution 
with the same central coverage:

\begin{equation}
\mathrm{CTR}
=
\frac{2\sqrt{2\ln 2}}
{2\Phi^{-1}(0.95)}
w_{90},
\end{equation}

where \(\Phi^{-1}\) is the inverse cumulative distribution function of the standard normal distribution.

Using the narrowest \(90\%\) interval makes the estimate less sensitive to tails and outliers than a fit performed over the complete residual 
distribution, while retaining a CTR value expressed in the conventional Gaussian-equivalent FWHM form~\cite{atkinson2025}.

The statistical uncertainty on the CTR is estimated by event bootstrap using 100 resamples. 
For each resample, events are drawn with replacement and the CTR is recomputed with the same procedure; 
the standard deviation of the resulting CTR distribution is reported as the uncertainty.

When comparing two timing methods on the same set of events, a paired bootstrap is used. 
The same resampled event indices are applied to both methods at each bootstrap iteration, 
preserving the event-by-event correspondence between the two residual distributions.
